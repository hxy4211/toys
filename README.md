用来玩 AI 工具的小玩具集合。一个仓库装多个小项目，每个玩具自成一体。

## 玩具列表

| 玩具 | 版本 | 说明 |
|---|---|---|

> 每个玩具的详细说明、操作方式、技术细节都在它自己目录下的 `README.md` 里。

## 小面宝宝桌宠

<img src="preview-states.png" width="820">

双击 `pet/启动小面.vbs` 启动。

- **移动鼠标** → 它会朝你的方向偏头
- **按住拖动** → 拖到任意位置，松手有果冻回弹，位置记住
- **单击** → 蹦一下 + 冒台词
- **双击** → 睡觉 / 叫醒（Zzz）
- **右键** → 菜单（说句话 / 睡觉 / 回右下角 / 隐身 10 分钟 / 退出）

只在 `DSH Desktop` 运行时出现，关掉 DSH 它自动隐藏。高度可在 `pet/config.json` 里改。

## 目录约定

```
toys/
├── README.md          ← 就是本文件：玩具索引 + 仓库约定
├── <玩具名>/          ← 每个玩具一个目录，自成一体
│   ├── README.md      ← 这个玩具的说明、操作方式、技术细节
│   ├── .gitignore     ← 排除该玩具的依赖/运行时产物
│   └── ...            ← 代码、素材、工具脚本
└── <共用素材>          ← 真正跨玩具共用的图/脚本才放根目录
```

## 新增一个玩具

1. 在根目录建 `玩具名/`，写自己的 `README.md` 和 `.gitignore`
2. 在本文件「玩具列表」表格里加一行
3. 提交后打标签 `玩具名-v1.0`

```bash
git add -A && git commit -m "feat(<玩具名>): 首个版本"
git tag -a <玩具名>-v1.0 -m "<玩具名> v1.0" && git push --tags
```

## 版本与标签约定

**标签带项目前缀**：`pet-v1.0`、`snake-v1.0`……不用裸 `v1.0`，否则玩具一多就分不清哪个是哪个的发版。

**日常推送**：

```bash
git add -A && git commit -m "<玩具名>: 说明"
git push                                    # 推分支
git tag -a <玩具名>-v1.1 -m "..." && git push --tags   # 推版本
```

## 仓库卫生

- 依赖、虚拟环境、构建产物一律 **gitignore**（`.pylibs/`、`node_modules/`、`dist/`、运行时状态文件）
- 大二进制（视频、模型、图片素材包）尽量别直接提交，必要时用 Git LFS —— Git 历史一旦写进大文件就很难清
- 现在的 `.gitignore` 写法是"每个玩具管好自己"，新玩具照抄一份即可
